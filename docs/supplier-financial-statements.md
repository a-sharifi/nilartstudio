# Recorded supplier financial statements — 2026-10-20

Supplier details retain their existing purchase-only statement. A separate finance.read-protected statement now combines immutable purchase liability changes with supplier cash allocations and linked financial reversals. It is also accessible independently at `/admin/finance/suppliers/{id}` from finance balances, without an inventory permission. Finance source documents have working deep links at `/admin/finance/movements/{id}`; purchase links require inventory access.

The projection includes posted purchase liability, receipt-linked return credits, cancellation credits, supplier payments/refunds and signed reversal allocations. Receiving goods has no liability/cash effect and creates no statement entry. Cash-account openings, unrelated expenses/transfers and customer refunds are excluded. Exact server Decimal strings and explicit IRT currency are preserved. Positive recorded balances are payable; negative ones are credit with the supplier. Original document dates and immutable source IDs, purchase IDs, event versions and correction/receipt IDs remain visible/exported.

Dates filter **recording dates in Asia/Tehran**, not original invoice dates. Prior recorded activity becomes the range's opening recorded balance. Same-time records have deterministic source/version/UUID ordering; a source timestamp cannot establish finer cross-document chronology. Supplier opening debt/credit is not configured by this stage. The UI/API/export explicitly flag this and never label the recorded subtotal as a confirmed complete account balance.

A single PostgreSQL snapshot projects monetary history and verifies purchase event completeness against stored versions/current liability. Missing history blocks the report rather than inventing movements. Reports are bounded to 10,000 effective supplier events. Pages bind to a content fingerprint over source history and filter scope; a changed ledger invalidates subsequent pages and the UI clears the mixed result. CSV/XLSX exports include the entire selected range and require both finance.read and finance.export; a changed fingerprint rejects the export. CSV formula prefixes are escaped and XLSX cells preserve exact values as text. There is no posting, automatic correction, external payment or migration in this feature.

Persian/English screens reuse shared filters, tables, compact icon row actions, Yekan Bakh, session cache clearing and responsive layouts. Supplier-editor navigation uses the existing unsaved-change guard. Financial source links load the authoritative document and preserve existing reversal permission rules. Loading, empty, changed-ledger, incomplete-history and permission states remain explicit.

Opening supplier debts/credits, full supplier-account settlement beyond purchase allocations, more than the bounded history volume, and full release acceptance remain pending. The broader 56-view admin release is still partial.
