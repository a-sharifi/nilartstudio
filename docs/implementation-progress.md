# پیشرفت پیاده‌سازی نیل‌آرت

تاریخ: ۲۰۲۶-۱۰-۱۲. این فایل مستقل از چک‌لیست ارسال پرامپت طراحی است.

## انجام‌شده و تست‌شده

- ریشه Git به `code/` منتقل شد؛ remote اصلی حفظ شد. هیچ commit یا push انجام نشد.
- کد در `Frontend/` و `Backend/`؛ منابع چاپ در `../design-prints/` خارج از Git.
- ۸۲۶ ورودی فایل/لینک در manifest ثبت و دوباره بررسی شدند؛ مغایرت صفر. manifest پیش از جابه‌جایی موجود نبود؛ انتقال با rename و بدون تبدیل فایل انجام شد.
- طراحی از revision مشخص وارد شد؛ ۴۲ فایل CSS بدون تغییر بایت حفظ شدند.
- مرجع Vite مستقل و سازگارسازی Next.js با کامپوننت‌های اصلی موجود است.
- خانه، کالکشن‌ها و جزئیات کالکشن به API متصل‌اند؛ مسیرهای غیرمتصل در حالت live عملیات نمایشی انجام نمی‌دهند.
- کاتالوگ DDD با روابط چندبه‌چند محصول/کالکشن/دسته و قیمت دقیق SKU.
- migration تا `0008` روی PostgreSQL اجرا شد.
- outbox تراکنشی، publisher confirm، retry محدود و consumer idempotent؛ فعلاً فقط handler زیرساختی ping.
- PostgreSQL، Redis، RabbitMQ، API، worker، web، MinIO توسعه و nginx همگی healthy شدند.
- Dockerfile، Compose توسعه/تولید، Makefile، CI و client تایپ‌شده OpenAPI آماده‌اند.
- محیط Python 3.12 جدید و وابستگی‌های frontend بازنصب شدند؛ وابستگی‌ها قفل‌اند.

## نتایج تست مرحله پایه (پیش از هویت)

- ۶۴ تست backend با PostgreSQL: موفق. اجرای بدون URL تست، ۱۰ تست یکپارچه را آگاهانه skip می‌کند.
- ۸ تست frontend: موفق؛ ۴ تست مرورگر: موفق.
- lint و typecheck هر دو برنامه: موفق؛ build محلی و container: موفق.
- Redis، ارتباط RabbitMQ/Celery و ارسال outbox با مصرف تکراری یک رویداد: smoke test واقعی اجرا شد.
- مرورگر روی Compose و دیتابیس واقعی: دو کالکشن Demo، ورود به جزئیات و reload بدون خطای JavaScript تأیید شد.
- scheduler اختیاری به‌صورت یک نمونه اجرا شد و healthy است.
- مقایسه hero مرجع و Next.js در عرض ۱۴۴۰ و ۳۹۰: ابعاد برابر؛ تفاوت کانال تصویر کمتر از ۰٫۳٪. این بررسی فقط hero است، نه تأیید بصری همه صفحات.
- audit وابستگی‌های npm پس از اصلاح: بدون آسیب‌پذیری گزارش‌شده.
- هشدار deprecation TestClient/httpx هنوز وجود دارد؛ تست‌ها موفق‌اند.

## داده توسعه

به‌صورت صریح فقط دو کالکشن Demo، دو دسته Demo، یک محصول مشترک و یک SKU بدون قیمت/موجودی در دیتابیس محلی ایجاد شدند. موجودی افتتاحیه، سند خرید، فروش یا مالی ایجاد نشده است.

## محدودیت‌ها و ادامه

### ادامه: زیرساخت هویت

- قواعد تلفن، هش scrypt، OTP هدف‌دار، origin امن و توکن نشست؛ ۲۵ تست قواعد موفق‌اند.
- migration `0005`: حساب و نشست هش‌شده، بدون ساخت کاربر آزمایشی.
- API ورود رمز، مشاهده نشست و خروج با CSRF؛ سناریوی PostgreSQL در schema موقت بررسی شد.
- پس از افزودن هویت، ۹۱ تست بک‌اند با PostgreSQL موفق شدند؛ ۸ تست frontend و typecheck همچنان موفق‌اند. origin نامعتبر، محدودیت تلاش و قطع Redis نیز تست شدند.
- این نتایج مربوط به برش اولیه هویت‌اند؛ ادامه در بخش زیر ثبت شده است.

### ادامه: OTP، ثبت‌نام، بازیابی و اتصال فرم رمز

- درخواست و تأیید OTP، ثبت‌نام پس از مجوز معتبر و بازیابی با ابطال نشست‌های قدیمی در بک‌اند پیاده شدند.
- چالش ۳ دقیقه، حداکثر ۵ تلاش، ارسال مجدد پس از ۶۰ ثانیه و مجوز ساخت رمز ۱۰ دقیقه و یک‌بارمصرف است.
- migration `0006` اجرا شد؛ هیچ حساب واقعی یا آزمایشی در دیتابیس برنامه ساخته نشد. حساب‌های تست فقط در schema موقت و rollback‌شونده بودند.
- ۱۰۰ تست بک‌اند با PostgreSQL و ۱۶ تست frontend موفق‌اند؛ lint، typecheck و build کانتینر موفق‌اند.
- ۵ تست مرورگر روی Compose موفق‌اند؛ ورود رمز با API واقعی در عرض ۳۹۰ و ۱۴۴۰، بدون overflow یا خطای JavaScript بررسی شد. RTL/LTR، تغییر زبان و reload فرم نیز تست شدند.
- فرم اصلی طراحی ورود رمز و انتخاب روش، در حالت live به API وصل‌اند؛ موفقیت نیازمند تأیید نشست است. کنترل‌های Demo در live وجود ندارند.
- SMS adapter هنوز غیرفعال است؛ endpoint بدون سرویس/کلید معتبر `sms_unavailable` می‌دهد. ارسال یا تحویل پیامک جعل نمی‌شود.
- اتصال رابط ثبت‌نام/OTP/بازیابی، RBAC، audit و مدیریت کامل نشست باقی‌اند. خروج API موجود است ولی رابط خروج هنوز متصل نیست.
- وضعیت خط بالا مربوط به برش قبلی است؛ اتصال فرم‌ها در ادامه زیر انجام شده است.
- مشکل حفظ IP قدیمی در nginx با DNS پویا اصلاح شد؛ بازسازی API بدون reload nginx و بازگشت readiness بررسی شد.
- CSS اصلی تغییر نکرد؛ اصلاح محدود grid فرم موبایل در stylesheet جدا ثبت شد. جزئیات در `docs/design-import.md`.

### ادامه: اتصال کامل فرم‌های ثبت‌نام، OTP و بازیابی

- کامپوننت‌های اصلی `OtpRequestForm`، `VerifyPage` و `RegistrationPasswordPage` به adapter واقعی API وصل شدند.
- مسیرهای فارسی/انگلیسی شماره، تأیید، ارسال مجدد و ساخت/بازیابی رمز قابل دسترسی‌اند؛ داده Demo مجوز معتبر محسوب نمی‌شود.
- چالش و مجوز فقط در حافظه همان تب نگهداری می‌شوند تا بین remountهای Next حفظ شوند؛ reload نیازمند شروع دوباره است. هیچ رمز، OTP یا grant در URL یا browser storage ذخیره نمی‌شود.
- خطای شبکه پس از عملیات حساس، نتیجه نامشخص محسوب می‌شود و ثبت مجدد متوقف می‌شود؛ پاسخ نامعتبر یا عدم تأیید نشست موفقیت نشان نمی‌دهد.
- سیاست رمز رابط با بک‌اند هماهنگ شد: ۱۲–۱۲۸ نویسه و حداکثر ۵۱۲ بایت.
- ۹ تست مرورگر موفق‌اند. جریان موفق ثبت‌نام/بازیابی در مرورگر با پاسخ‌های کنترل‌شده API تست شد؛ این به معنی ارسال واقعی پیامک نیست.
- ۲۲ تست frontend، lint و typecheck موفق‌اند؛ build نهایی Docker اجرا و سرویس web سالم شد. شمارش نویسه Unicode رمز نیز با Python هماهنگ و تست شد.
- فرم‌های درخواست فارسی/انگلیسی روی API واقعی محلی، خطای SMS غیرفعال را نشان دادند؛ در عرض ۳۹۰ بدون overflow و خطای JavaScript بررسی شدند.
- بک‌اند در این برش تغییر نکرد؛ ۱۰۰ تست PostgreSQL مربوط به بررسی قبلی همچنان مرجع آن است.
- سرویس واقعی SMS، خروج UI، RBAC، audit، پنل مشتری و ادغام سبد هنوز باقی‌اند؛ هیچ حساب واقعی seed نشده است.

### ادامه: خروج واقعی و بازیابی امن CSRF

- صفحه اصلی طراحی خروج به API وصل شد؛ ابتدا نشست بررسی می‌شود، خروج فقط پس از تأیید کاربر انجام می‌شود و موفقیت نیازمند بررسی دوباره نبود نشست است.
- `POST /auth/session/csrf` برای دریافت توکن تازه پس از reload اضافه شد؛ مبدأ دقیق، نشست معتبر و محدودیت Redis ضروری‌اند. خطای Redis دسترسی را باز نمی‌کند.
- توکن قبلی باطل می‌شود؛ حذف نشست نیز تطبیق CSRF را در همان دستور SQL دوباره کنترل می‌کند.
- پیام تب دیگر صرفاً باعث بررسی API می‌شود و مدرک خروج نیست. نتیجه نامشخص، خروج خودکار مجدد ایجاد نمی‌کند.
- فرم‌های فارسی و انگلیسی خروج در عرض ۳۹۰ بدون overflow بررسی شدند. CSS اصلی تغییر نکرد.
- ۱۰۱ تست بک‌اند روی PostgreSQL، ۲۵ تست frontend و ۱۱ تست مرورگر موفق‌اند؛ build و بررسی نوع/lint موفق‌اند.
- سرویس پیامک، RBAC، audit، پنل مشتری، cache خصوصی و ادغام سبد همچنان باقی‌اند؛ هیچ انتشار عمومی یا حساب seedشده ایجاد نشد.

### ادامه: پایه نقش‌ها و مجوزها

- نقش‌های مشتری، هنرمند، عملیات، مالی و ادمین با مجوزهای صریح و بدون wildcard تعریف شدند.
- migration `0007` اجرا شد؛ حساب موجود فقط مشتری می‌شود و ثبت‌نام جدید در همان تراکنش نقش مشتری می‌گیرد. هیچ ادمینی seed یا ارتقا داده نشد.
- endpoint خصوصی `/api/v1/auth/access` و dependency قابل استفاده مجوزها اضافه شدند. نقش‌ها در هر درخواست از دیتابیس خوانده می‌شوند؛ نشست قدیمی نقش حذف‌شده را نگه نمی‌دارد.
- ۱۱۳ تست بک‌اند با PostgreSQL موفق‌اند؛ تست HTTP نقش‌ها در برنامه موقت تست اجرا شد، نه با ایجاد عملیات بازپرداخت واقعی.
- ۲۵ تست frontend و typecheck موفق‌اند؛ ظاهر طراحی تغییر نکرد.
- ۱۱ تست مرورگر نیز دوباره موفق شدند؛ endpoint دسترسی برای مهمان خطای ۴۰۱ و `no-store` برمی‌گرداند.
- اتصال guard به endpointهای تجاری آینده و کنترل مالکیت/تخصیص، مدیریت نقش همراه audit، ایجاد نخستین ادمین با تأیید اپراتور و پنل‌های واقعی همچنان باقی‌اند. جزئیات: `Backend/ACCESS.md`.

### ادامه: بک‌اند پروفایل مشتری

- دریافت و ذخیره پروفایل فقط برای صاحب نشست با مجوز self-account اضافه شد؛ شماره، نقش و account_id در ورودی ویرایش پذیرفته نمی‌شوند.
- CSRF و Origin بررسی می‌شوند؛ نسخه قدیمی با ۴۰۹ رد می‌شود و تغییرات تازه بازنویسی نمی‌شوند.
- migration `0008` اجرا شد؛ نام فرضی یا پروفایل واقعی وارد نشد.
- ۱۲۱ تست بک‌اند با PostgreSQL، ۲۵ تست frontend و ۱۱ تست مرورگر موفق‌اند؛ lint، typecheck، ساخت کانتینر API و readiness موفق‌اند.
- اتصال فرم اصلی طراحی پروفایل، حذف داده‌های نمایشی پوسته پنل در live و حالت‌های واقعی بارگذاری/تعارض هنوز باقی‌اند. ظاهر فرانت‌اند در این برش تغییر نکرد.
- جزئیات قرارداد و محدوده در `Backend/PROFILE.md` ثبت شد.

### ادامه: اتصال فرم طراحی پروفایل

- `ProfilePage` در پوسته اصلی `DashboardPage` به API وصل شد؛ مسیرهای `/fa/account/profile` و `/en/account/profile` فعال‌اند.
- اطلاعات نمونه، ابزار پیش‌نمایش و علامت‌های اعلان/پشتیبانی فرضی در live حذف شدند. CSS اصلی حفظ شد.
- دریافت، خطای دسترسی، ذخیره واقعی و تعارض نسخه پیاده شدند؛ ورودی در تعارض باقی می‌ماند تا کاربر نسخه جدید را صریحاً بارگذاری کند.
- ذخیره با CSRF تازه و پیش‌شرط مالک انجام می‌شود؛ پاسخ مالک متفاوت یا نتیجه نامشخص، موفقیت محسوب نمی‌شود. backend مالک متفاوت را از header رد می‌کند، نه اینکه آن را هدف ویرایش قرار دهد.
- خروج در تب دیگر و focus باعث بررسی دوباره API می‌شوند؛ پیام مرورگر مدرک مجوز نیست.
- تغییر زبان هنگام ویرایش تأیید می‌خواهد؛ هشدار beforeunload و لینک‌های خود پنل موجودند. کنترل کامل Back مرورگر و چرخه مشترک cache خصوصی همچنان باقی‌اند.
- ۱۲۱ تست PostgreSQL، ۲۹ تست frontend و ۱۴ تست مرورگر موفق‌اند؛ فرم موبایل فارسی/انگلیسی در عرض ۳۹۰ بدون overflow بررسی شد. جریان موفق رابط با پاسخ‌های کنترل‌شده تست شد و حساب واقعی seed نشد.
- سایر بخش‌های پنل، تغییر شماره، ایمیل و audit هنوز متصل نیستند. جزئیات در `Backend/PROFILE.md`.

### مانع محیط در ساخت نهایی

- کامپایل Next.js، typecheck/lint و ۲۹ تست frontend موفق بودند. ۱۴ تست مرورگر روی تصویر قبلیِ همین برش موفق شدند؛ تغییر نهایی متن‌ها کامپایل شد، اما ذخیره تصویر نهایی شکست خورد.
- Docker هنگام نوشتن `metadata_v2.db` خطای I/O داد. دیسک میزبان ۱۰۰٪ و فقط حدود ۴۲۷ MiB آزاد بود؛ سپس socket Docker ناپدید شد و localhost:8080 از دسترس خارج شد.
- هیچ فایل، volume، چاپ یا داده کاربر حذف نشده است. پاک‌سازی سراسری Docker یا حذف Docker.raw انجام نشد.
- ادامه اجرای محلی نیازمند آزادکردن فضای دیسک و بازیابی Docker است. پس از آن سلامت PostgreSQL و سرویس‌ها و build نهایی باید دوباره بررسی شوند؛ فعلاً وضعیت محیط healthy نیست.

### بررسی مجدد محیط و ساخت مستقل

- فضای آزاد میزبان به حدود ۲٫۹ GiB رسید (پس از build حدود ۲٫۷ GiB). هیچ فایل یا volume توسط این مرحله حذف نشد.
- Docker Desktop process موجود است، اما daemon/status پاسخ نمی‌دهد و socket آن موجود نیست. سرویس اصلی localhost:8080 هنوز قابل بازیابی/تأیید نیست.
- build نهایی Next.js خارج از Docker موفق شد؛ lint و typecheck هر دو برنامه موفق شدند.
- اجرای محلی تست‌ها: ۹۵ backend موفق و ۲۶ تست PostgreSQL آگاهانه skip شدند؛ ۲۹ تست frontend موفق‌اند. این جایگزین ۱۲۱ تست PostgreSQL قبلی نیست.
- ۱۴ تست مرورگر روی build نهایی در اجرای موقت فرانت‌اند پورت ۳۱۰۰ موفق شدند؛ پاسخ‌های حساس API کنترل‌شده بودند، نه سرویس‌های واقعی خاموش‌شده. اجرای موقت پس از QA متوقف شد.
- برای ادامه سرویس کامل، Docker Desktop باید بازیابی/راه‌اندازی مجدد شود؛ هیچ reset، حذف Docker.raw، پاک‌سازی سراسری یا راه‌اندازی مجدد خودکار انجام نشد.

- محتوای عمومی هنوز پشت client boundary سازگاری است؛ SSR کامل و استخراج layoutهای route-specific باقی مانده‌اند.
- قیمت/موجودی قابل خرید و صفحات جزئیات محصول هنوز به جریان خرید واقعی وصل نیستند.
- تکمیل هویت و RBAC، رسانه و bucket، خرید/تولید، COST، checkout، پرداخت، مالی و اجرای هنرمند نیازمند پیاده‌سازی بعدی‌اند.
- MinIO عمومی قابل pull نبود؛ نسخه توسعه از source commit پین‌شده ساخته و اجرا شد. upstream آرشیوشده است؛ production به image سازگار و بررسی‌شده امنیتی نیاز دارد.
- backup/restore، تأیید سرویس‌های واقعی و سیاست‌ها شرط انتشارند؛ هیچ انتشار عمومی انجام نشده است.
- scheduler اختیاری باید فقط یک نمونه داشته باشد؛ handlerهای تجاری و UI رسیدگی به eventهای ناموفق هنوز وجود ندارند.

## دسترسی محلی

فروشگاه توسعه: `http://localhost:8080`

ورود با رمز: `http://localhost:8080/fa/auth/login/password` (بدون حساب seedشده).

اجرای معمول از ریشه `code/`: `make up`، `make migrate` و `make check`.
فایل `.env` توسعه gitignored است؛ برای production از credentials جدا استفاده شود.
پوشه‌های موقت upload/download و محیط قدیمی در ریشه workspace حفظ شده‌اند.


### ادامه در clone جدید Linux — ۲۰۲۶-۱۰-۱۲

- محیط این میزبان با محیط قدیمی Docker Desktop متفاوت است؛ Docker فعال و فضای دیسک کافی است. هر ۸ سرویس اکنون healthy و `http://localhost:8080` در دسترس است.
