# Supplier opening confirmations and corrections — 0050

Finance can explicitly record an evidenced external supplier opening debt, credit or zero. This is an opening-account confirmation, not a purchase, receipt, payment, inventory adjustment or gateway operation. Amounts are exact decimal strings in explicit IRT. The dated balance must exclude every purchase/payment already recorded in this system. Staff must confirm that exclusion, provide a source reference and reason, and choose an opening date strictly before both today and the supplier's first recorded purchase-post/payment day (Tehran time). This avoids presenting an overlapping same-day balance as an opening import. Original invoice dates remain separate from recording dates.

A correction replaces the opening amount through a signed delta linked to the latest retained opening event. The original opening date stays frozen. Both the old receipt and correction remain available, including explicit zero confirmations. No silent update/delete or fictitious cash/stock movement occurs. This stage does not settle opening debts/credits; do not use a correction as a substitute for recording a real supplier payment. Independent settlement against opening balances remains pending.

`/api/v1/admin/finance/suppliers/{id}/opening` returns the current receipt or null when unconfigured. `/opening/history` pages immutable revisions; `/opening/commands/{key}` saves a versioned command or recovers its actor-owned receipt. Reads require finance.read. Writes independently recheck finance.write and finance.read under the live account lock, then acquire the established finance→procurement locks. Exact retry returns the original receipt even after subsequent corrections. Reused intent, stale versions, a wrong correction link or an overlapping/future date are explicit conflicts. Entry, audit and the deduplicated background event commit atomically; failure rolls everything back.

Migration 0050 adds only `supplier_opening_events`. It creates no opening data for existing suppliers. Opening entries join the recorded supplier statement as their own source; zero confirmations are retained. The report distinguishes opening changes, purchase liability and net payments, keeps both the source date and recording timestamp, and exports the configuration flag, correction links and exact balances. Date filters still use recording dates, so a newly imported historical opening is visible when recorded, not silently backdated into an earlier report. Existing fingerprints are invalidated when new opening evidence changes the ledger.

The Persian/English finance supplier page includes opening/history, debt/credit selection, an explicit zero path, source reference/reason, renewed confirmation after a conflict, stable uncertain-result recovery and draft navigation guards. Saving clears the previous report; reload displays fresh totals. Read-only finance staff see history without write controls. Supplier detail pages link to this finance workspace; inventory permission is not needed for opening management. Shared typography, dropdowns, compact buttons and statement icon actions are preserved.

The full sandbox release is still partial. Supplier opening settlements, external payouts/gateway settlements, complete checkout policies, catalogue/BOM/media/artist workflows and full 56-view acceptance remain outstanding. Real money movement and production activation remain excluded.
